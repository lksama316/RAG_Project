# 知识管家（knowledge_hub）

> 一个基于 RAG 的企业知识库问答系统：上传 PDF / Markdown，用自然语言提问，从你自己的资料里找出答案。

---

## 项目背景

企业内部的技术手册、产品说明、安全规范大多以 PDF 形式散落在各处，想查一个具体问题（比如"这台设备怎么调温度"）往往要翻几十页文档。通用大模型虽然能对话，但它没见过你的私有资料，直接问要么答不上来，要么一本正经地胡说。

**知识管家**要解决的就是这件事：把文档解析、切分、向量化后建成可语义检索的知识库，用户提问时先从库里检索出最相关的片段，再交给大模型"看着资料回答"。答案有出处、可溯源，资料更新后重新导入即可，不需要重新训练模型。

一句话概括整体思路：**先建索引，再问答**。

---

## 核心功能

### 资料导入

- **多格式解析**：支持 PDF 与 Markdown；PDF 通过 MinerU 云端服务解析成结构化 Markdown。
- **图片理解**：自动提取文档中的图片，用多模态模型生成中文摘要并替换原文引用，让图里的信息也能被检索到。
- **智能切分**：按标题层级切分文档，并做"长切短合"（过长拆分、过短合并），每块都带父级标题与序号，便于溯源。
- **商品主体识别**：自动判断整篇文档属于哪个产品/型号，为每个知识块打上商品标签。
- **向量化入库**：用 BGE-M3 生成稠密 + 稀疏双向量，写入 Milvus 并建立索引。
- **幂等导入**：同一份文档重复导入会覆盖旧版本，不会产生重复数据。

### 知识问答

- **商品确认**：先从提问中识别商品型号并与商品库核对——型号明确就精确检索，说法模糊就反问用户，完全匹配不上则自动退回全库检索。
- **混合检索**：稠密 + 稀疏向量加权融合（0.8 / 0.2），兼顾整体语义与关键词匹配。
- **HyDE 检索**：先让 LLM 写一段"假设的理想答案"再去检索，改善短问题的召回效果。
- **联网搜索**：通过百炼 MCP 补充实时信息，与本地检索结果一起参与排序。
- **多路融合（RRF）**：将多路检索结果合并去重、统一打分。
- **重排序**：用 Rerank 模型对候选文档重新打分，并做断崖截断，只把高质量资料喂给大模型。
- **流式输出**：基于 SSE 推送节点进度与逐字答案，长任务也能看到实时反馈。
- **多轮对话**：对话历史存于 MongoDB，支持上下文追问。

## 系统架构

系统由两条独立的流程组成，各自作为一个服务运行。

### 导入流程（资料进库）

```
上传文件 (PDF / MD)
   │
   ├─ 入口分发 ── 判断文件类型，PDF 走解析、MD 直接进入下一步
   │
   ├─ PDF 转 Markdown ── 调 MinerU 云端解析，下载并解压结果
   │
   ├─ 图片处理 ── 多模态模型生成图片摘要，图片上传 MinIO，替换原文引用
   │
   ├─ 文档切分 ── 按标题切分 + 长切短合，产出 500~2000 字的知识块
   │
   ├─ 商品识别 ── LLM 判断文档所属商品，回填到每个知识块，并写入商品名向量集合
   │
   ├─ 向量化 ── BGE-M3 为每个知识块生成稠密 + 稀疏向量（分批处理，避免显存溢出）
   │
   └─ 入库 ── 按文档标题清理旧数据后批量写入 Milvus，回填 chunk_id
```

### 查询流程（提问得到答案）

```
用户提问
   │
   ├─ 商品确认 ──┬─ 型号明确 ──→ 继续检索（带商品过滤）
   │             ├─ 型号模糊 ──→ 反问用户「您想问的是哪个产品？」，直接返回
   │             └─ 无匹配 ────→ 清空过滤，走全库检索
   │
   ├─ 三路并行召回 ──┬─ 向量检索（改写后的问题）
   │                ├─ HyDE 检索（问题 + 假设答案）
   │                └─ 联网搜索（MCP）
   │
   ├─ RRF 融合 ── 本地两路结果合并去重、累加打分
   │
   ├─ 重排序 ── 合并联网结果，Rerank 精排 + 断崖截断
   │
   └─ 答案生成 ── 组装 Prompt（问题 + 上下文 + 历史），流式生成答案
                  → 写入历史 → SSE 推送 final 事件
```

### 两个服务

| 服务     | 端口 | 职责                                                |
| -------- | ---- | --------------------------------------------------- |
| 导入服务 | 8000 | 接收文件上传，后台执行导入流程，提供任务进度查询    |
| 查询服务 | 8001 | 接收提问，后台执行查询流程，通过 SSE 推送进度与答案 |

| 类别       | 技术 / 服务                   | 用途                                   |

| 联网搜索   | 百炼 DashScope MCP            | 补充实时信息                           |
| 前端       | 原生 HTML / JavaScript        | 上传、聊天、进度展示                   |

## 快速开始

### 环境要求

- **Python 3.11**
- **MongoDB**、**Milvus**、**MinIO** 服务可达（本地或远程均可）
- **BGE-M3 模型**已下载到本地（需配置模型路径）
- **MinerU API 令牌**有效（[申请地址](https://mineru.net/apiManage/docs)）
- 如需 GPU 加速：可用的 CUDA 环境（BGE-M3 默认跑在 `cuda:0`，也可改为 CPU）

## 使用示例

一次完整的"上传文档 → 提问 → 得到答案"过程：

**第一步：上传资料**

1. 打开 `http://127.0.0.1:8000/import.html`，选择一个 PDF 或多份文档上传。
2. 前端为每个文件拿到一个 `task_id`，并以约 1 秒的间隔轮询任务状态。
3. 页面上会依次显示进度：`PDF转Markdown → 图片处理 → 文档切分 → 商品识别 → 向量化 → 导入向量库`。
4. 看到全部节点完成后，资料就已经进入知识库，可以开始提问了。

**第二步：提问**

5. 打开 `http://127.0.0.1:8001/chat.html`，输入问题，例如"这台设备怎么调节转印温度？"。
6. 后端先识别问题中的商品型号：
   - 如果型号明确，只在该商品的知识块里检索；
   - 如果说得含糊，系统会反问"您是想问以下哪个产品：A、B？"，你补充型号后再问即可；
   - 如果问题与商品无关（例如"什么是 Vibe Coding？"），系统自动改为全库检索。
7. 系统并行发起三路召回（向量检索 / HyDE 检索 / 联网搜索），经 RRF 融合与 Rerank 精排后生成答案。

**第三步：看答案**

8. 页面上进度条实时更新当前执行到的节点，答案逐字流式显示。
9. 答案末尾会附上引用到的资料片段，如果原文包含图片，图片也会一并展示。

## 项目亮点 / 技术难点

**1. 混合检索（Dense + Sparse）**
BGE-M3 一次输出稠密与稀疏两种向量，稠密负责整体语义、稀疏负责关键词匹配，检索时用 `WeightedRanker` 按 0.8 / 0.2 加权融合。相比单一稠密向量，对型号、专有名词这类"字面必须对上"的查询召回明显更好。

**2. HyDE：先写假设答案，再去找资料**
"怎么调温度？"这类短问题语义信息太少，直接检索容易跑偏。系统先让 LLM 基于问题写一段"像说明书里会出现的答案"，再用"问题 + 假设答案"一起生成向量去检索——向量更接近真实文档的分布，召回率更高。

**3. RRF 多路融合**
两路检索各有偏好、结果互有出入。系统用 `score += weight / (k + rank)`（k=60）对每路结果打分，同一个知识块在多路中都靠前就累加得分，天然实现"去重 + 融合"，让多路都认可的片段排到前面。

**4. 断崖截断：宁可少给，也不给不相关的内容**
精排按分数降序后，从第 3 名往后检测相邻分数是否出现"断崖"（绝对差 ≥ 0.5 或相对差 ≥ 50%），一旦出现就在该处截断，最终保留 3~10 条。喂给大模型的上下文质量比数量更重要。

**5. 全流程流式反馈**
导入与查询都是耗时任务，系统把流程中的每个节点进度与生成中的答案通过 SSE 实时推给前端。用户能看到"现在跑到哪一步了"，而不是对着一个转圈的页面等待。

**6. 商品维度过滤：让检索更精准**
文档导入时自动识别所属商品，检索前先确认用户问的是哪个型号，把检索范围收窄到该商品的知识块。既提升了相关性，也让"问错产品"这种问题提前暴露。

## 常见问题

**Q：上传或提问后既没有进度也没有答案？**
`LangGraph` 的 `workflow.run(stream=True)` 返回的是**懒加载生成器**，不迭代它图就不会真正执行。确保代码形如 `for event in workflow.run(init_state, stream=True): pass`。

**Q：导入 Markdown 时报错提示缺少 `md_content`？**
入口节点对 MD 文件没有读取文件内容，导致后续节点拿不到正文。MD 分支在入口处也需要把文件内容读进状态。

**Q：下载 MinerU 解析结果时报 `SSL: UNEXPECTED_EOF`？**
Windows 系统代理把 CDN 请求也一并代理，导致握手失败。为该域名配置代理例外，或绕过代理直连。

**Q：服务启动失败，报 MongoDB 连接错误？**
对话历史模块在**模块加载时**就初始化连接并建索引，MongoDB 不可达会直接导致服务起不来。请先确认 MongoDB 服务可用。

**Q：问非商品类问题被拒绝，回答"未找到相关产品"？**
早期逻辑在商品匹配失败时直接拒绝。现已改为：匹配不上就清空商品过滤、走全库检索，因此"什么是 XXX"这类通用问题也能正常回答。

**Q：日志里出现 `Minio init failed`？**
启动时连不上 MinIO（内网或防火墙问题）。该失败不会阻塞导入主流程，但图片上传与展示会受影响，建议检查 MinIO 服务与网络连通性。
